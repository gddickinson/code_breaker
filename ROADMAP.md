## Lessons learned
- Look at the cut lines before training on them: three line cutters in a row cut lines in half or merged them, and two training runs had to be stopped (Round 88b).
- 113 silver-labelled lines are too few to beat a general OCR engine: the fine-tuned reader beat Tesseract (0.26 against 0.32 character error) but not RapidOCR (0.19) (Round 88b).
- A wait loop must not match itself: anchor the process pattern (it happened twice, Rounds 86 and 88b).
- When output length can change, the score must not reward length: common words inserted anywhere beat the average quadgram, so a free search filled every text with 'the'; a code word must earn its place by fitting its context, one symbol per word (Round 88a).
- Keep running totals consistent: a margin subtracted on one side of a comparison and not the other made every move look like an improvement and wrecked correct keys (Round 88a).
- A statistic that separates cases in one language can fail in another: a frequent German letter spaced like a word divider (KL 0.22); decide by decoding both ways (Round 88a).
- Measure on real material before trusting synthetic scores: the crack recovered 48 of 49 synthetic ciphers but 11 of 74 real-material items, and three of its 'readable' calls on them were wrong (Round 87).
- A method must refuse input it cannot have produced: ADFGX run on ordinary letters became a 600-symbol homophonic solve that could make 70 letters read as anything (Round 87).
- A saved model that checks its class list switches itself off when a class is added; the crack still ran, so only a test noticed (Round 87).
- Model the language people actually wrote: abbreviated ad French scored 2-16 sd below novels, so the solver's own language choice ranked French near last (Round 87).
- Historical practice changes the arithmetic: alphabets without W make Vigenere shifts run modulo 25, and a 26-letter attack read none of 22 such ads (Round 87).
- Test on text the model never saw: with 40,000-character corpora, controls drawn from the training text scored 1.00 everywhere; held out, Hebrew substitution fell to 0.71 and Arabic to 0.89 (Round 86).
- Removing every combining mark is not neutral: it turned Russian й into и and Ukrainian ї into і, deleting letters from the alphabet; only stress accents should go (Round 86).
- When a server refuses (HTTP 429), back off and stop; a fixed one-second retry turned a rate limit into hundreds of refused requests (Round 86).
- A wait loop that greps the process list for a name matches its own command line and never ends (Round 86).
- Read a multi-part source the way it was assembled: the corpus reader cut each file at the first Gutenberg END marker, so 11 of 12 new corpora silently shrank to their first book (Dutch to 6,050 characters) (Round 85b).
- Choose a statistic for what the cipher has done: rank-sorted frequencies survive substitution but barely tell languages apart; taking the minimum of two distances let the weak one swamp the strong one. Solving quickly in each language and comparing with real text of that language was far stronger (0.54 to 0.97) (Round 85b).
- A reading that shuffled letters match is not a possible reading: random text had been reported as 'possible' whenever coverage passed 50% (Round 85b).
- With large alphabets, higher-order entropy from a few thousand tokens is badly underestimated for real and shuffled streams alike; compare against shuffles at the order the data can support (Round 84).
- The null must vary what the message depends on: shuffling words in a text without spaces changes nothing, so every-n-th-letter controls failed until such texts shuffled letters (Round 83).
- Too unlikely to be chance is not the same as a secret message: the D-Day crossword words had a common cause.
- What a person sees and what OCR reads part company early: hidden words were plain to the eye at -15 dB in noise and unreadable to OCR below 0 dB; a statistic designed for the task (large-scale structure) reached -10 dB (Round 82).
- A detector's threshold belongs to the kind of input: structured sounds like birdsong need a far higher bar than noise, so report the score with reference ranges rather than one verdict.
- Check a rule against its recorded examples, not only its stated form: the French note cipher as written maps H to A, but the recorded HAYDN motif keeps H as B-natural (Round 81).
- A many-to-one code has no exact decryption: report the most likely reading and test it by re-encryption and by accuracy against the original.
- A value-permutation null fits undeciphered scripts: it keeps the corpus's word shapes and sign frequencies and destroys only the sound values under test (Round 80).
- Test on the real thing early: the glyph recogniser looked strong on every synthetic test and read 1.6% of real carvings; a day's fine-tuning on photographs, tested on held-out pictures, took it to 92% (Round 79).
- Split held-out data by source picture, not by sign, so the test never shares a photograph with training.
- Pooling evidence by multiplying probabilities is fragile to a few strongly wrong items; a confidence-weighted vote held up better once the model changed.
- Debug captures must be protected from the test suite: tests posting the sample picture overwrote the user's capture, and a comparison ran on the wrong image (Round 85).
- A language identifier trained on unequal amounts of text favours the languages with less of it (their unseen-n-gram penalty is milder); train on equal amounts.
- Check every installed component end to end: 6 of 49 translators silently returned nothing until a sentence splitter that supports them was chosen.
- A live sample exposes what a synthetic control misses: the scanner merged closely spaced runes that the widely spaced test pages never had; tight pages are now part of the control (Round 78b).
- Steganalysis thresholds need the right clean images: newsprint that was once a JPEG false-alarms 90%; a guard that could not be calibrated was dropped and the limit is stated instead.
- Compare whole methods per case instead of tuning one radius: row-and-column cuts and part joining fail in different places, and choosing between them per page beat every single setting.
- Test the whole pipeline, not the model alone: the unseen glyph test failed at 7% because the model was shown raw grey images while training had clean backgrounds; one shared preprocessing step raised it to 78% (Round 78).
- Widening training to harder distortions can cost accuracy on easy inputs: clean Egyptian pages fell from 94% to 72% top-1; keep easy controls beside the hard ones.
- Check a detector on empty input: Otsu thresholding on blank paper split the texture itself into 'signs' until a contrast floor was added.
- A carved artefact can be a test suite: the Rök stone's recorded resolutions checked the rune order, the ætt numbering and the shift direction at once (Round 77b).
- Check every history claim against a saved page before writing it: two of the seven planned entries had no support in the sources and were left out.
- A dictionary hit rate means little without a random baseline: random Egyptian strings hit 40% because the language has many one- and two-consonant words, so the real 87% is the evidence, not the 87% alone (Round 77).
- An exotic alphabet is only relabelling: relabelling unknown symbols as letters lets every substitution attack run, but a lossy script spelling (merged letters) defeats language tests and needs its own word-level recovery (Round 76).
- Scripts that start worker processes must run from a file with a main guard on macOS; a heredoc script breaks the process pool.
- Sign values are data like ciphertexts: take them from a recorded table and test them, and refuse a value the tables cannot give (the Ptolemy cartouche's MdC mnemonics) rather than filling it from memory (Round 75).
- Pre-registering by commit works and costs one test run: the Round 74 gate was in git before its result existed, so the negative stands without argument.
- Do not run the test suite while the hunt runs: the Workbench crack test has a 45-second budget and failed once under load (passed 3 of 3 alone).
- A blind solve that recovers a documented key is the strongest check on a key-based reading: three families' blind keys matched their tables on 97.7-99.6% of occurrences (Round 73).
- When a test count changes after adding data, look for duplicates before updating the test: Round 71 raised a family test to 6 when one ad had been counted twice (Round 73).
- Size the null from the bar, not from habit: the first all-keys screen (bar 2.6e-5) used 20,000 shuffles, floor 5e-5, and could pass nothing; stage 2 now takes max(20,000, 2/bar) (Round 72, the same trap as Round 71).
- Check that a null can reach the bar: 200 shuffles give p >= 1/201, above a Bonferroni bar of 0.0045, so the first C. H. run could not pass whatever the ad said (Round 71).
- A documented key can travel between writers: V. E. 3 used the C. H. Vigenere key but let it run across words; test documented keys on other signatures, with and without restarts.
- Leads read from OCR keep a low tier until they are transcribed: Round 70's twelve early 2119 ads all passed once read from the scans, so a weak tier often measured the OCR, not the cipher.
- Beating a shuffled copy proves only that the order is non-random. Results must also match a real solve of that size and contain real words.
- Short-text solvers overfit: the homophonic solver beat the true plaintext's score until a letter-frequency penalty was added.
- A null built from real initials is much stricter than shuffled letters.
- A "survivor" in an elimination can be vacuous: count how many constraints actually applied.
- On Apple Silicon, integer table-lookup search is faster on one CPU core than on the GPU.

- Temperature must scale with text length; a fixed schedule quietly fails on long messages.
- Ground-truth diagnostics on solved ciphers can localise a modelling error to an exact position.

- Simple transforms before substitution are worth trying everywhere: one reversal unlocked a real message.

- The stricter verdict correctly demoted Dorabella and seven sweep entries from 'signal' to 'structure only'.

- Compare a cipher against its solved sibling: Beale 2 made the correlation test interpretable.

- Plant a known answer in the exact shape of the real problem, so that zero survivors means something.

- A poor score for a crude copy of a published theory says nothing about the theory itself.

- Near-miss classification is fine when the next step can test several guesses cheaply.

- Do not type ciphertext from memory: the query for the pigeon message used a wrong letter that the published form corrected.

- Contradiction search is powerful: one wrong plug guess eliminates itself, which is why the bombe needs only a short crib.

- Test your own best explanation by building the rival: the honest Beale encoder overturned last round's reading.
- Before buying more search, compare the true answer's score with what the solver found.

- Check whether a new idea is even distinct: short Beale passages reduce to whole-document offsets, so that avenue was rejected.
- Judge a language model against the best answer a key can actually produce, not the idealised published text.

- Recheck favourable comparisons for fairness: the 5-gram 'win' on Z340 compared against an unreachable text.

- A scorer that handles the planted error case is what real historic ciphers need: quadgram methods reward clean-looking wrong text.
- A better scorer does not by itself help search: polishing from wrong starts stays in local optima.

- A failed planted control stops the line: the Z340 numbers from that method were not interpreted.
- When several rounds of effort on one benchmark give shrinking returns, park it and move on.

- With short texts and periods up to 20, solvers overfit: require coverage plus a control at that length.

- Word coverage alone is fooled by dense solvers on short texts: the control gate is doing necessary work.
- A benchmark of real solved ciphers shows limits synthetic tests hide.

- Look at the source: seven 'decryptions' were plain French ads that the solver mapped back to themselves.
- A database's 'unsolved' label can include text that was never enciphered.

- Use the historical record: writers' documented systems beat general statistics on short ads.

- Independent routes to one answer beat a single score: a blind solve and a writer's own table reached the same KP text.
- When a parser finds 1 of 60 tables, do not trust the run: check counts before reading results.

- Adding search options raises the chance level: two short readings (H and one R ad) now fall below the stricter shuffled threshold, so keep their earlier evidence separate.

- A finder that adds names needs deduplication against what is already tracked, or lists fill with aliases.
- Keyword searches return off-topic papers: filter and spot-check them.

- Merging two OCR versions by best coverage slightly lowered the control (15 against 16 for Otsu alone): picking the most readable output can favour a wrong reading.
- Improving the input beat adding more cipher systems.

- Planted single-step transpositions are much easier than real benchmark ciphers: a passing control does not mean the method generalises.
- Bigram search over 676 values per symbol overfits at 1,000 letters; penalising letter frequencies did not rescue it.

- Page scripts share a global scope: one repeated name silently removes a whole file, so a test now forbids clashes.
